# V2: реализованный backend и границы прототипа

Это **V2-demo**, а не завершённая исследовательская платформа из
[полного технического задания](09-v2-technical-spec.md). Основной проверяемый сценарий —
«Снегопад»: погода → пропускная способность → задержка → очередь служб → обращение →
перераспределение бригады → две ветки → парный эксперимент по нескольким seed.

Бэкенд объединён с интерфейсом `codex/aygerim-v2-preview`. Его кнопка «Снегопад · V2»
создаёт сценарий и прогон, отправляет шаг worker и читает реальные метрики через `/api`.
Не все описанные здесь возможности получили экраны; они доступны через HTTP,
Swagger `/docs` и демонстрационный скрипт. Калькулятор V1 доступен по `/?mode=v1`.

## Два независимых режима

| Режим | Данные и результат | Что сохраняется |
|---|---|---|
| `official-v1` | Исходные пять районов, 14 мер, бюджет 100, официальный AQoL | Прежние формулы, ограничения, контрольный результат `56.54307` |
| `dynamic-v2` | Отдельный синтетический снимок, по умолчанию шесть районов; временные ряды и ledger | Seed, параметры, очередь событий, журнал, checkpoint, команды и manifest |

V2 не использует исходный датасет V1 как измеренные транспортные, финансовые или
демографические данные. Наименования районов — метки синтетического города. Его цены,
население, вероятности и мощности **не являются статистикой или прогнозом Астаны**.
Метрики V2 не пересчитывают и не подменяют официальный Score V1.

## Запуск и демонстрация

Из корня репозитория:

```bash
docker compose up --build -d --wait
docker compose exec api python -m scripts.demo_v2
```

Если установлен локальный Python, результат и архив прогона можно сохранить на хосте:

```bash
python -m scripts.demo_v2 --url http://127.0.0.1:8000 --out artifacts/v2-demo.json --archive artifacts/v2-run.zip
```

Скрипт создаёт сценарий, прогревает его 120 модельных минут, создаёт checkpoint и две
ветки. В одной из веток бригада из другого района назначается в Нуру. Обе ветки
проходят ещё 720 минут. Затем скрипт получает метрики, причинную трассу обращения,
парный отчёт по seed `11, 23, 37`, evidence-сводку и ZIP-экспорт.
Он не пересчитывает городские показатели и не требует положительного эффекта
вмешательства: направление и величину изменения определяет серверная модель.

Процессы Compose:

- `api`: V1, V2, Data Gate, OpenAPI и чтение результатов.
- `worker`: ограниченные по размеру пакеты симуляции и выполнение ансамблей.
- `db`: PostgreSQL с именованным томом для сценариев, прогонов и экспериментов.
- `web`: объединённый preview-интерфейс и калькулятор V1; полный набор V2-экранов ещё не реализован.

`GET /v2/health` показывает heartbeat worker. Если команда принята, но модельное время
не движется, проверьте `docker compose logs worker api`. API не выполняет длинные
шаги в обработчике HTTP. Для локального запуска API и worker должны использовать
одинаковые `AKIM_DATABASE_URL` или `AKIM_V2_STORE`; без PostgreSQL используется SQLite.

`AKIM_RUN_TOKEN` включает Bearer-проверку прав на управление V2. Пустое значение —
локальный однопользовательский demo-профиль, а не публичный production-доступ.
Для административных действий Data Gate используется отдельный `AKIM_ADMIN_TOKEN`.
Не публикуйте demo-профиль в интернете без авторизации и сетевых ограничений.

## Архитектура и воспроизводимость

`engine/v2/domain` содержит чистые переходы состояния, генератор синтетических входов,
параметры и инварианты. Здесь нет HTTP, файлового ввода-вывода и импортов V1.
`engine/v2/application` управляет сценариями, очередями команд, ветвлением и
экспериментами через порт `DocumentStore`. `engine/v2/infrastructure` реализует
PostgreSQL/SQLite, отдельный worker и публикацию входов через Data Gate.
`services/api/v2.py` — HTTP-адаптер; он не содержит формул симуляции.

Стабильный scheduler упорядочивает события по модельному времени, приоритету и ID.
Случайные значения детерминированы ключом seed / семейство веток / модуль / сущность /
модельное время: изменение одной ветки не расходует RNG-поток другой.
Checkpoint хранит состояние вместе с очередью будущих событий; прикладной журнал
позволяет повторить последующие переходы и сравнить хеш результата.

Каждый пакет worker атомарно сохраняет состояние, события, метрики и остаток команды.
После перезапуска процесс продолжает сохранённую очередь; повторная HTTP-команда с тем
же ключом не применяется второй раз. Несовпадение `expectedStateVersion` возвращает
`409`, а не молча перезаписывает изменения. Совпадение на другом оборудовании или
после изменения кода/версий зависимостей не обещается.

Экспорт `GET /runs/{id}/export` — ZIP с `manifest.json`, `run.json`, `scenario.json`
и `metrics.json`. В нём сохранены начальный снимок, версии, seed, параметры,
checkpoint, журнал и финальное состояние. Это материал для воспроизведения и анализа;
автоматический импорт такого архива как нового прогона пока не реализован.

## HTTP-контракты для фронтенда

Актуальный контракт HTTP публикуется в `/openapi.json`; формы запросов описаны в
`services/api/v2_contracts.py`. Идентификаторы ресурсов нужно брать из ответов API,
а не конструировать на клиенте.

| Запрос | Назначение |
|---|---|
| `GET /v2/catalog` | Версии, снимок Data Gate, районы, параметры с диапазонами, статусы модулей |
| `POST /scenarios` | Неизменяемый сценарий `dynamic-v2`, погода `snow/clear`, режим времени |
| `POST /runs` | Прогон `{scenarioId, seed, horizon}`; стартует на паузе |
| `GET /runs/{id}` | Время, статус, версия, состояние, checkpoint и `pendingCommand` |
| `POST /runs/{id}/commands` | Часы и управленческие решения |
| `POST /runs/{id}/checkpoints` | Контрольная точка после завершения текущего шага |
| `POST /runs/{id}/branches` | Независимая ветка `{checkpointId}` |
| `POST /runs/{id}/replay` | Проверка checkpoint + журнала по хешу |
| `GET /runs/{id}/events` | SSE; `id` события — монотонный `seq` |
| `GET /runs/{id}/events?stream=false&after=0` | Страница журнала и `nextSeq` |
| `GET /runs/{id}/metrics` | Временные ряды и evidence с единицами и источниками |
| `GET /runs/{id}/trace/{eventId}` | Причинные предшественники `causedBy` |
| `GET /runs/{id}/population`, `/development`, `/flows`, `/politics` | Срезы стратегических подсистем |
| `POST /experiments`, `GET /experiments/{id}` | Асинхронный парный ансамбль и отчёт |
| `POST /assistant/messages` | Детерминированная сводка результатов, `mode: rule-based` |

Создание прогона, ветки, эксперимента и отправка команды требуют заголовка
`Idempotency-Key`. Для команды ключ заголовка должен совпадать с полем тела:

```json
{
  "commandId": "operator-step-1",
  "idempotencyKey": "operator-step-1",
  "expectedStateVersion": 0,
  "type": "clock.step",
  "payload": {"minutes": 120},
  "issuedBy": "local-user"
}
```

`202` означает принятие, не завершение расчёта. Клиент дожидается
`pendingCommand: false`, затем читает новую `stateVersion`. Ошибки имеют форму
`{error: {code, field, message}}`. При разрыве SSE клиент передаёт последний `seq`
в `Last-Event-ID`; журнал остаётся авторитетным источником. Числа из evidence
содержат единицы и статус происхождения; `null` нельзя отображать как ноль.

Команды часов: `clock.pause`, `clock.resume`, `clock.step`, `clock.speed`, `clock.cancel`.
`clock.speed.payload.speed` — размер продвижения в модельных минутах за пакет, **не
гарантированный коэффициент к настенным часам**. Оперативный режим использует шаги
физических процессов 15 минут и горизонт до 7 суток. Стратегический режим агрегирует
их по дням, а потоки — по фиксированным 30-дневным модельным месяцам; максимум — 120
таких месяцев. Эти два разрешения нельзя считать численно взаимозаменяемыми.

Управленческие команды прототипа: `crew.reassign`, `project.start`,
`development.moratorium`, `developer.requirement`, `budget.submit`, `budget.amend`,
`zoning.change`, `land.allocate`, `hearing.schedule`, `promise.announce`.
Планирование будущего `startMinute` поддержано для назначения бригады; другие типы
решений не следует считать универсальным календарём политик. Проекты ограничены
школами и дорогами. Правила ресурсов, резерва бюджета и зон проверяет доменный слой.

## Что действительно моделируется

| Подсистема | Реализация | Существенное ограничение |
|---|---|---|
| Погода, транспорт, службы | Снег меняет мощности, поездки, физическую очередь и работу бригад | Районный агрегат, не граф улиц и не мультимодальная маршрутизация |
| Жители и обращения | Взвешенные представители, опыт поездки, обращение со ссылкой на событие | Не реальные люди, не опрос и не оценка общественного мнения |
| Школы | Мощность, штат, финансирование, нехватка мест | Нет клиник и индивидуального расписания посещений |
| Демография | Возрастные группы, рождение/смерть, внутренняя и внешняя миграция | Три возрастные группы и синтетические коэффициенты без калибровки |
| Застройка | Синтетические участки, зонирование, проекты, ввод и жилищный фонд | Нет кадастровой геометрии, сноса и полного рынка жилья |
| Финансы | Cash, резерв, расходы/доходы, CAPEX/OPEX, переводы между секторами | Заимствования отключены, реальные налоговые правила не реализованы |
| Политика | Синтетические группы, голосования, слушания, обещания | Не модель реальных партий, акторов или результатов выборов |
| Эксперименты | Парные seed, медиана разницы, эмпирические p05–p95, нарушения бюджета | Seed-интервал не является доверительным интервалом эффекта в реальном городе |
| AI-штаб | Evidence-сводка без внешнего ключа и автоматического изменения города | LLM-диалог, council и автоматический исследовательский агент V2 не подключены |

Статусы `implemented`, `partial`, `not-implemented` и конкретные ограничения доступны
в каталоге. Озеленение, безопасность, историческая калибровка и holdout-проверка
пока не реализованы. Полная проверка среза «Десять лет роста» со всеми вариантами
финансирования, включая займ, не заявляется: заимствования в прототипе отключены.

Для production также нужны полноценные роли/пользователи, квоты и жизненный цикл
хранилища, индексы/партиционирование журналов, архивирование, нагрузочные измерения,
наблюдаемые датасеты, проверка параметров и внешняя валидация механизмов.
Сейчас run хранится атомарным JSON-документом; это удобный надёжный формат демо,
но не обещание производительности на сотнях тысяч агентов.

## Проверки этого слоя

Контроллер и HTTP проверяются целевым набором:

```bash
python -m unittest tests.v2.test_controller tests.v2.test_http -v
```

Набор проверяет восстановление незавершённого шага новым контроллером, отсутствие
повторного применения команды, конфликт версии, pause/resume/cancel, независимость
веток, replay и целостность checkpoint, HTTP-валидацию и авторизацию, восстановление
курсора событий, evidence и отсутствие мутаций от текста ассистенту, ZIP-экспорт.
Доменные инварианты и качество входов проверяются отдельно в `tests/v2/test_domain.py`
и `tests/data_gate/test_v2.py`. Это не заменяет ещё не проведённые нагрузочные тесты
и экспериментальную проверку модели на реальных данных.
