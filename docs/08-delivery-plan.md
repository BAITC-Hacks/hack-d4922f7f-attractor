# Реализация, контрольные ворота и приёмка

## 1. Принцип планирования

Сначала обязательный воспроизводимый V1, затем полноценный вертикальный срез V2,
затем расширение процессов и научная проверка. Проект исследовательского масштаба
нельзя честно обещать реализовать целиком за один хакатон. Каждый этап оставляет
работающий результат и явно обозначает отсутствующие возможности.

Календарные сроки V2 устанавливаются после подтверждения команды, данных и пилотных
замеров. Ниже — зависимости и критерии завершения; это не фиктивный почасовой дедлайн.
Плановый хакатонный минимум допускает три параллельных человеческих потока:
расчёты/API, интерфейс, AI/интеграция. Владелец интеграции назначается явно.

## 2. Этапы

| Этап | Результат | Зависимость | Ворота завершения |
|---|---|---|---|
| P0 | Контракты, репозиторий, fixtures, CI | — | Схемы согласованы, каркас запускается |
| P1 | Движок V1 и импорт исходника | P0 | Golden и правила проходят без LLM |
| P2 | Полный интерфейс V1 и AI | P1 | Пять решений → результат → объяснение |
| P3 | Движок времени, ledger, replay, Data Gate MVP | P0; после защиты V1 при дефиците времени | Пауза/шаг/ветка/восстановление воспроизводимы |
| P4 | V2 транспорт + службы + жители + погода | P3 | Сквозная цепочка с реальными переходами состояния |
| P5 | Все пять направлений и стратегические финансы | P4 | Связанные подсистемы, балансы, квартальные проекты |
| P6 | Многоканальные обращения, исследовательский AI | P4–P5 | Evidence, проверенные эксперименты, cost controls |
| P7 | Калибровка и независимая проверка | P5 + исторические данные | Отчёт holdout и неопределённости |
| P8 | Масштабирование и живые источники | P7 + performance baseline | SLO, свежесть данных, восстановление |

Data Gate развивается вместе с P3–P8. AI для V1 не ждёт V2. Динамический прототип
может развиваться после стабилизации P1, но не задерживает завершение задания.

## 3. Backlog с критериями готовности

### P0 — фундамент

- [ ] Схемы Scenario/Result/Event/Manifest; fixtures и контрактные тесты.
- [ ] Зафиксировать трактовку пяти решений; ADR и версия правил.
- [ ] Утвердить стек, зависимость/lock-файлы, formatter/linter и CI.
- [ ] Создать `.env.example`, конфигурацию и режим без AI.
- [ ] Определить владельцев модулей и протокол изменения контрактов.

### P1 — точный V1

- [ ] Перевести источник в JSON, проверить 5 районов/10 показателей/14 мер.
- [ ] Валидатор всех ограничений, включая глобальные и районные конфликты.
- [ ] Эффекты, лаги, синергии, clip, Score, декомпозиция.
- [ ] Golden 52.55768 и 56.54307; тесты свойств и граничных значений.
- [ ] API evaluate/validate; стабильные ошибки; отсутствие мутации исходника.
- [ ] Поиск допустимых локальных альтернатив; полный перебор опционален.

### P2 — готовность хакатонного продукта

- [ ] Районы, каталог, пять слотов, бюджет, объяснение блокировок.
- [ ] Экран результата: до/после, минимум, критические показатели и стоимость.
- [ ] AI с проверенными фактами и fallback; вопросы и проверенные альтернативы.
- [ ] Сохранение/экспорт и сравнение двух сценариев.
- [ ] Чистая установка по README, тесты, демо и резервный сценарий.
- [ ] Полезность объяснения проверена на вопросах, а не только наличии текста.

### P3 — ядро V2 и Data Gate

- [ ] Scheduler, стабильный порядок, RNG-потоки, clocks и состояния run.
- [ ] Ledger, резервирование, идемпотентные команды и журнал событий.
- [ ] Checkpoint с очередью и RNG; ветки; replay и восстановление worker.
- [ ] CSV/JSON/GeoJSON-import, schemas, quality report, immutable snapshot.
- [ ] SSE с reconnect, агрегаты, пауза/шаг/скорость и отмена.

### P4 — первый динамический срез

- [ ] Синтетические семьи, возраст/доход/расписание, представительные веса.
- [ ] Дорожная сеть, маршруты, загрузка и ограничения транспорта.
- [ ] Бригады, очередь инцидентов, задания, время и ресурсы ремонта/уборки.
- [ ] Погодный сценарий с влиянием на конкретные мощности.
- [ ] Обращения от моделируемого опыта; полный жизненный цикл.
- [ ] Ветка без вмешательства и с решением акима; парное сравнение.

### P5 — полнота города

- [ ] Зелень, посадки/уход/вода; отсутствие необоснованного прогноза AQI.
- [ ] Школы/поликлиники, возрастной спрос, штат, очередь и доступность.
- [ ] Экспозиция, вероятность и регистрация событий безопасности.
- [ ] ЖКХ/отходы, износ, профилактика и отказы.
- [ ] CAPEX/OPEX, сроки проектов, доходы города, семьи и внешняя экономика.
- [ ] Реестр коэффициентов с единицами/источниками/диапазонами.
- [ ] Тесты связей, двойного счёта, разных временных масштабов.

### P6–P8 — исследование и эксплуатация

- [ ] Адаптеры разрешённых каналов; дедупликация и происхождение обращений.
- [ ] NPC с локальным опытом, AI-штаб, строгие tools и проверка evidence.
- [ ] Ансамбли, sensitivity, baselines, holdout, error by group.
- [ ] Измерение пользы AI против шаблонного отчёта.
- [ ] Экспорт эксперимента, model/data cards, отчёт ограничений.
- [ ] Профилирование, контроль памяти и стоимости, тест аварийного восстановления.
- [ ] Обновление реальных источников с учётом задержек и версий границ.

## 4. Ответственность команды

| Область | Владелец роли | Интерфейс интеграции |
|---|---|---|
| Математика V1 / evaluator | Инженер модели | Result и golden fixtures |
| Динамика V2 | Инженер симуляции | State/Event/Module contracts |
| Данные | Инженер данных | Snapshot и quality report |
| Backend / инфраструктура | Backend-инженер | API, jobs, replay, storage |
| UI | Frontend-инженер | Контракты API и события |
| AI | AI-инженер | Tools, evidence и eval suite |
| Исследования | Аналитик/исследователь | Протокол, baselines, validation report |

Один человек может совмещать роли. Это распределение ответственности, а не требование
нанять семь человек. На маленькой команде сокращается одновременный объём, не проверка
формул и происхождения данных.

## 5. Цели производительности — до измерения

| Операция | Начальная цель | Условие измерения |
|---|---|---|
| V1 evaluate | p95 < 100 мс | Серверное время, без сети/LLM |
| V2 UI | Обновления агрегатов 1–2 раза/с | Не каждый NPC в каждом кадре |
| Команда pause | Подтверждение < 1 с | Между ограниченными пакетами событий |
| AI | Первый полезный ответ целевой < 10 с | Провайдер/модель указаны в отчёте |
| Replay | Совпадение контрольного состояния | Зафиксированное окружение |

Benchmark фиксирует CPU, RAM, версии, число агентов/событий, горизонт, warmup,
количество повторов, p50/p95, пиковую память и стоимость. Цели не являются уже
достигнутыми характеристиками. Для V2 скорость относительно модельного времени
измеряется отдельно для каждого масштаба и конфигурации.

## 6. Риски и действия

| Риск | Признак | Действие |
|---|---|---|
| Разрастание объёма | Нет полного V1, но много NPC | Заморозить V2 до P2 |
| Нет данных | Коэффициенты выбираются ради красивого результата | Синтетический режим, диапазоны, model card |
| Неидентифицируемость | Разные параметры одинаково объясняют историю | Дополнительные наблюдения/упрощение |
| Дорогой AI | Вызов для каждого агента | Агрегация, представители, лимиты |
| Невоспроизводимость | Ветки расходятся без вмешательства | RNG streams, стабильный scheduler, replay |
| Ложная точность | Один seed и один красивый график | Ансамбли и интервалы |
| Перегрузка UI | Отставание от событий | Агрегирование и backpressure |
| Несовместимость с заданием | V2 меняет официальный Score | Отдельные mode/rules/data версии |

## 7. Демонстрация

### Обязательное демо V1, 3 минуты

Показать одинаковый старт → собрать контрольный набор → получить 56.54307 →
попробовать нарушить бюджет/конфликт → изменить меру → показать дельты и объяснение.
Затем открыть README и контрольные тесты. На экране видна версия модели.

### Дополнительное демо V2, 4 минуты

Запустить город → снегопад снижает мощности → растут задержки/очередь → появляются
обоснованные обращения → аким перераспределяет ресурс → сравнить две ветки из одного
checkpoint → открыть событие-основание → показать диапазон по серии прогонов.
Статус неполных подсистем виден; синтетическая природа и режим времени обозначены.

## 8. Definition of Done релиза

Функция реализована, проверена на положительных/отрицательных случаях, задокументирована,
видна в сквозном сценарии, сохраняет версии и не ломает воспроизводимость.
README содержит фактический статус, требования, точные команды установки/запуска/тестов,
контрольные числа, конфигурацию AI, режим без ключа, ограничения, демо и troubleshooting.
Ни одна галочка этого плана не считается выполненной только из-за появления документа.
