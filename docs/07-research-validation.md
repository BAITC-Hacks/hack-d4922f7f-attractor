# Исследовательский протокол и проверка

## 1. Что означает высокий научный стандарт

Каждое существенное утверждение сопровождается вопросом, механизмом, данными,
экспериментом и ограничениями. Сложность модели не является доказательством качества.
До калибровки V2 — лаборатория условных сценариев. Термин «валидированный прогноз»
разрешён только для конкретной метрики, территории и горизонта с измеренной ошибкой.

## 2. Гипотезы исследования

| ID | Вопрос | Эксперимент | Критерий |
|---|---|---|---|
| H1 | Даёт ли динамика пользу против статической модели? | Одинаковые входы, исторический holdout | Ошибка/качество решений против baseline |
| H2 | Важна ли неоднородность жителей? | Однородные агенты против групп дохода/возраста | Изменение хвостов и распределения доступности |
| H3 | Важны ли связи подсистем? | Полная модель против отключённых связей | Разница эффектов при внешнем шоке |
| H4 | Устойчиво ли решение? | Разные погода, цены, параметры и seed | Диапазон результата, вероятность нарушения ограничений |
| H5 | Помогает ли AI пользователю? | Шаблонный отчёт против AI при одинаковых данных | Понимание компромиссов, время и ошибки решения |

Гипотеза может не подтвердиться. Отрицательные результаты сохраняются, а не скрываются
выбором удачного seed. Порог полезного улучшения и бюджет эксперимента фиксируются
до просмотра тестовой выборки.

## 3. Baselines

V1 exact calculator; V2 без вмешательства; простые сезонные/инерционные прогнозы
для наблюдаемых рядов; агрегированная модель без агентов; однородные агенты;
система без межмодульных связей; отчёт без LLM. Сравнение идёт на одинаковых данных,
горизонтах, вычислительных условиях и доступной на дату прогноза информации.

## 4. Verification — правильно ли реализовано

- Golden tests V1 и свойства валидатора.
- Балансы населения, денег, очередей, воды/ресурсов в соответствующих модулях.
- Неотрицательность запасов и мощности, причинный порядок событий.
- Идемпотентность команд, сохранение/восстановление и изоляция веток.
- Нулевой спрос, нулевая мощность, отказ всех маршрутов, отсутствие средств.
- Сходимость по временному шагу и числу агентов.
- Контрактные тесты всех входов/выходов модулей и единиц измерения.
- Повторное применение импортированного события не меняет результат второй раз.

Свойства монотонности проверять только там, где они действительно следуют из модели:
добавление дороги в сложной сети не обязано автоматически улучшать все показатели.

## 5. Validation — соответствует ли механизм наблюдениям

1. Определить наблюдаемый target: поездки, очередь, аварии, длительность ремонта.
2. Зафиксировать сопоставление с моделью, географию, единицы и временное окно.
3. Разделить train/calibration/validation/test по времени; при возможности оставить
   отдельные районы для пространственной проверки. Не перемешивать связанные записи.
4. Подбирать только идентифицируемые параметры по calibration-части.
5. Сравнить с простым baseline на отложенных данных.
6. Измерить ошибку по районам и группам, а не только среднюю.
7. Проверить устойчивость вне калибровочного режима и обозначить границу применимости.

Примеры метрик: MAE для времени/очередей, распределения P50/P90, ошибка потоков,
покрытие прогнозных интервалов; Brier score и calibration для вероятностных событий.
Нельзя выбрать метрику после просмотра результата, чтобы скрыть неудачу.
Если данных нет, допустимы тесты механизмов и expert review, но не заявление точности.

## 6. Неопределённость

Раздельно учитывать случайность событий, неизвестность параметров, ошибку входных
данных и выбор структуры модели. Ансамбль seed отражает только первый источник.
Для остальных нужны распределения параметров, альтернативные данные/модели.

Для A/B использовать одинаковые внешние сценарии и парные RNG-потоки. Потоки keyed
по run family, модулю, агенту/событию и времени; добавление события в ветке не должно
сдвигать все последующие случайные числа другой ветки.

Начальный пилот, например 30 парных прогонов, используется для оценки дисперсии,
а не как универсальная гарантия. Число прогонов и правило остановки определяются
требуемой точностью. Показывать среднее/медиану, интервалы, хвостовые риски и долю
нарушений бюджета/доступности. Интервал случайных исходов отличать от интервала
оценки среднего. Интервалы не покрывают все ошибки структуры автоматически.

## 7. Чувствительность, абляции и идентифицируемость

Варьировать стоимость времени, склонность обращаться, эффект погоды, мощность служб,
инфляцию, доходы и коэффициенты utility в обоснованных диапазонах. Сначала локальный
screening, затем глобальный анализ для наиболее влиятельных параметров.

Проверять компенсацию параметров: одинаковый средний результат может достигаться
разными механизмами. Для различения нужны дополнительные наблюдения. Если параметр
не идентифицируется, фиксировать диапазон и показывать устойчивость решения к нему.

Абляции: без погоды, без неоднородности, без финансовых ограничений, без связей,
без LLM. Нужна измеримая добавленная польза каждого усложнения.

## 8. Протокол одного эксперимента

```yaml
experiment_id: snow-response-v1
question: Does crew reallocation reduce disruption within the same budget?
baseline: no-reallocation
intervention: reallocate-one-crew
primary_outcome: service-unavailability-hours
secondary_outcomes: [travel-time-p90, backlog, expenditure]
constraints: [same-initial-state, same-weather, budget-feasible]
data_snapshot: immutable-id
model_version: revision
parameter_set: version
seeds: preregistered-list
warmup: specified-duration
horizon: specified-duration
analysis: paired-difference-with-interval
stopping_rule: predefined-compute-budget-and-precision
```

Warmup исключает искусственный эффект пустых очередей при старте. Для прогноза
критично корректное начальное состояние, а не только одинаковый seed.

## 9. Причинность и управленческие выводы

Вмешательство в симуляции даёт причинный эффект внутри заданной модели. Это ещё
не доказательство такого же эффекта в реальном городе. Реальные причинные оценки
требуют подходящего исследовательского дизайна и проверки смешивающих факторов.
Оптимизация одного индекса может ухудшать другие исходы: показывать Pareto-компромиссы,
не только «лучший балл». Особенно проверять худший район и группы с низким доступом.

## 10. Артефакты исследования

- Model card: назначение, механизмы, допущения, применимость, ограничения.
- Data cards и lineage; таблица параметров с источниками и диапазонами.
- Manifest прогона, lock-файлы, конфигурация, seed, checkpoint и журнал.
- Независимый evaluator, golden fixtures, отчёт тестов и benchmarks.
- Notebook/скрипт анализа с воспроизводимыми таблицами и графиками.
- Отчёт calibration/holdout, отрицательные результаты и sensitivity.
- ADR выбора ABM, временного шага, агрегации и модели наблюдений.

До калибровки провести обзор первичных научных публикаций по выбранным механизмам:
описание ABM, транспортный выбор, очереди, синтетическое население, валидация и UQ.
Библиография должна содержать проверенные источники и связь с конкретным решением;
в этом плане не заявляется, что такой обзор уже проведён.
