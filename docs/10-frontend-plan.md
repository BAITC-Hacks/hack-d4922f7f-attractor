## 3. Архитектура фронтенда

Сохраняем чистые слои, добавляем модули под V2:

```text
apps/web/src/
  domain/            типы (генерируются из packages/contracts) + чистые функции форматирования
  application/
    ports.ts         V1Api, DataGateApi, RunsApi, AssistantApi, EventStream
    usecases/        evaluateScenario, compareScenarios, runControl, …
  infrastructure/
    http/            httpV1Api, httpDataGateApi, httpRunsApi, httpAssistantApi
    fixtures/        офлайн-режим V1 (только для демо без бэкенда)
    sse/             EventStream с Last-Event-ID и backoff
    map/             адаптер MapLibre: слои, стили, choropleth
  presentation/
    screens/         City, Decisions, Result, Lab, DataGate, Assistant
    components/      ScoreCard, DistrictTable, IndicatorHeatmap, BudgetBar, EventFeed, …
```

Правила:

- **Числа только из API.** Никакого пересчёта Score, бюджета или дельт на клиенте, кроме
  отображения суммы стоимостей в слотах до запроса (с пометкой «предварительно»).
- **Состояние** — `useReducer` на экран + лёгкий кеш запросов. TanStack Query — если понадобится
  отмена, ретраи и инвалидация; Redux не нужен.
- **Карта — через адаптер.** `presentation` не вызывает `maplibregl` напрямую, чтобы подложку и
  слои можно было заменить.
- **Ключи API на фронт не попадают.** AI вызывается только через бэкенд ([01](01-product.md) §6).

## 4. Этап F1 — завершить V1

Порядок = порядок пользовательского сценария ([01](01-product.md) §3, V1).

### 4.1 Город (исходное состояние)

- Таблица 5 районов × 10 показателей из `GET /catalog`: тепловая шкала, значения < 40 выделены
  как критические, в подписи — порог.
- Доля населения и итог D по району. Базовый AQoL `52.55768`, остаток бюджета `100`.
- Версии снимка, правил и модели в подвале — видны всегда ([08](08-delivery-plan.md) §7).
- **Приёмка:** данные совпадают с `data/source-dataset.ru.txt`; две критические ячейки Нуры видны.

### 4.2 Решения

- 5 слотов: мера → район (для районных мер), город — без района.
- Бюджет-бар: сумма стоимостей, остаток, превышение подсвечено **до** отправки.
- Кнопка «Рассчитать» зовёт `validate`, затем `evaluate` (как сейчас).
- Ошибки валидатора — у конкретного слота по `field` и `code`: `budget_exceeded`,
  `direction_limit_exceeded`, `measure_conflict_district`, `measure_conflict_global`,
  `district_required`, `district_not_allowed`, `duplicate_measure`, `selection_count`.
- Подсказка о правилах: «ровно 5 разных мер, не более 2 из одного направления, бюджет 100».
- **Приёмка:** каждое правило датасета показывается человеческим текстом у нужного слота;
  набор за 110 не отправляется на расчёт, а объяснение видно.

### 4.3 Результат

- **AQoL до → после** крупно, Δ со знаком.
- Декомпозиция из 4 строк: `0.7 × D_avg`, `0.3 × min(D_d)`, `− N_crit`, итог — каждая «до / после / Δ».
- Районы: D до / после / Δ, отметка слабейшего района.
- Тепловая карта показателей «после» с Δ и отметками пересечения порога 40.
- Карта: районы подкрашены по Δ D (дивергентная шкала), легенда с единицами.
- **Приёмка:** на контрольном наборе видно `56.54307`, `N_crit` стал 0, обе ячейки Нуры
  пересекли 40 — всё из ответа API.

### 4.4 AI-разбор

- Кнопка «Разобрать сценарий» → `POST /v1/analysis` (или `/assistant/messages` в режиме V1).
- Блоки: **Сильные стороны · Риски · Последствия · Рекомендации**. Каждое утверждение с
  числом ссылается на поле результата (evidence), при наведении подсвечивается строка/ячейка.
- Плашка режима: `AI` или `Без AI: правила` ([09](09-v2-technical-spec.md) §12.3, поле `mode`).
- Рекомендация-замена показывается как **кнопка «Применить и пересчитать»**: подставляет
  набор в слоты и зовёт `validate` + `evaluate`. Сама она ничего не применяет.
- Состояния: загрузка, таймаут, ошибка AI (расчёт при этом остаётся на экране).
- **Приёмка:** без ключа на бэкенде блок работает в режиме «правила»; ни одно число в тексте
  не рендерится из LLM, только из ответа движка.

### 4.5 Альтернативы и сравнение

- `POST /v1/alternatives`: список проверенных наборов с AQoL и стоимостью, кнопка «Применить».
- Сравнение двух сценариев бок о бок: AQoL, районы, показатели, стоимость (опция ТЗ «сравнение
  результатов нескольких команд» — это тот же экран с N сценариями).
- **Приёмка:** применённая альтернатива пересчитывается сервером и даёт ровно заявленный AQoL.

### 4.6 Экспорт

- JSON сценария: selections + versions + результат. Markdown-сводка для презентации
  (опция ТЗ «автоматическая генерация краткой презентации» — поверх AI-разбора).

### 4.7 Офлайн-режим

- Без `VITE_API_BASE_URL` — фикстуры с постоянной плашкой «Демо-данные. Расчёт выполняет сервер».
- **Нельзя** выдавать фикстуру за расчёт для произвольного набора (см. B5).

## 5. Этап F2 — экраны V2

Экраны из [01](01-product.md) §4, API из [09](09-v2-technical-spec.md) §13. Начинать после P3 на
бэкенде; до этого — на фикстурах событий.

### 5.1 Экран города с часами

- Карта/схема, 5 направлений, модельное время, скорость (×1…×N), кнопки пауза/шаг/старт.
- Команды через `POST /runs/{id}/commands` с `Idempotency-Key` и `expectedStateVersion`.
- **Приёмка:** пауза подтверждается < 1 с; конфликт версии показывается как «состояние
  изменилось, обновите», а не молча.

### 5.2 Поток событий (SSE)

- `EventStream`: переподключение с `Last-Event-ID`, экспоненциальный backoff, индикатор
  «соединение потеряно / восстановлено, догружено N событий».
- Рендер агрегатов 1–2 раза/с: события копятся в буфере и сбрасываются в `requestAnimationFrame`.
  Не рисовать каждого NPC в каждом кадре ([08](08-delivery-plan.md) §5).
- **Приёмка:** разрыв сети на 10 с не теряет ни одного события в ленте.

### 5.3 Панель акима

- Бюджет по ledger: `cash`, `reserved`, `available_to_commit`, обязательства и проекты с
  этапами. Форма решения: тип, ресурсы, дата начала, срок. Ошибки ledger у полей.
- **Приёмка:** повторная отправка того же решения не удваивает резерв.

### 5.4 Панель района

- Группы жителей, объекты и их загрузка, очереди, показатели, обращения, **качество данных**
  (источник, допущения, пропуски — UC-2).

### 5.5 Лента событий и причинная трасса

- События с территорией, временем, источником и последствиями.
- «Почему?»: от события/метрики по `causedBy` к событиям-причинам и изменениям состояния (UC-8).

### 5.6 AI-штаб

- Диалог с контрактом ответа: summary, claims с градацией (наблюдение / расчёт /
  интерпретация / гипотеза), evidence-ссылки, ограничения, предложения.
- Предложенный эксперимент показывается планом со стоимостью; запуск — только по кнопке.
- «Совет жителей»: 8 карточек персон, консенсус и конфликты, одна предложенная замена;
  плашка `AI council live` / `deterministic council`.

### 5.7 Лаборатория

- Ветки: дерево run → checkpoint → branch. Сравнение двух веток по выбранным метрикам.
- Ансамбли: медиана, интервал, хвосты, доля нарушений ограничений; **нельзя** показывать один
  seed как результат ([07](07-research-validation.md) §6).
- Протокол эксперимента (YAML из [09](09-v2-technical-spec.md) §5.2) — видимый и экспортируемый.

### 5.8 Data Gate

- Загрузка файла → отчёт качества (critical / warning / info с полями) → mapping (что пошло в
  модель, что осталось в raw) → preview изменений → публикация с явным принятием
  предупреждений → история и откат.
- API уже есть в `data_gate` (методы сервиса); UI строится по
  `packages/contracts/data-gate-*.schema.json`.

## 6. Сквозные требования

| Требование | Как выполняем |
|---|---|
| Единицы видимы | Каждое число отображается компонентом `<Value value unit />` |
| Неизвестное ≠ 0 | `null` показывается как «нет данных», прочерк с подсказкой |
| Происхождение величины | Бейдж по `Evidence.status`: наблюдение / симуляция / допущение / расчёт |
| Карта без точной геометрии | Подпись «схема» |
| Доступность | Клавиатура для слотов и карты, текстовая таблица как альтернатива карте, контраст AA |
| Ошибки | Единый вид `{code, field, message}` у поля; частичный результат и отмена видимы |
| Язык | Русский интерфейс; коды ошибок не показываются пользователю без текста |

## 7. Тесты

- **Unit (Vitest):** нормализаторы ответа API, форматирование, reducer экрана решений.
- **Контрактные:** фикстуры валидируются JSON Schema из `packages/contracts` в CI — фикстура,
  расходящаяся с API, ломает сборку.
- **E2E (Playwright):** контрольный сценарий — выбрать 5 мер → `56.54307`; набор за 110 →
  ошибка бюджета у слота; конфликт M4 + M7 в одном районе → ошибка; AI-разбор без ключа →
  режим «правила». Для V2 — разрыв SSE и восстановление.
