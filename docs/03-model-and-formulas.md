# Формулы, ограничения и проверка

## 1. Источник истины

[Исходный датасет](../data/source-dataset.ru.txt) сохраняется без изменения.
H = 8 кварталов, бюджет B = 100, пять районов, десять показателей, 14 мер.
Все показатели направлены одинаково: больше означает лучше.

Веса населения p = (.27, .24, .20, .13, .16) для Есиля, Алматы, Сарыарки, Байконура, Нуры.
Веса показателей в порядке T1,T2,E1,E2,S1,S2,B1,B2,C1,C2:
w = (.10,.10,.09,.11,.11,.11,.09,.09,.10,.10). Обе суммы равны 1.

## 2. Валидация portfolio-v1

- Ровно пять разных measureId, каждый существует в каталоге.
- Сумма полной стоимости ≤ 100. Лаг не уменьшает стоимость.
- Не более двух мер одной категории; следовательно, охвачено минимум три категории.
- Районная мера имеет один допустимый districtId, городская — null.
- M1/M3 несовместимы глобально.
- M4/M7 и M5/M13 несовместимы при одинаковом районе.
- Остаток бюджета не приносит бонуса.
- Невалидный набор: score = null, список причин. Никогда не возвращать 0 как валидный Score.

Версия all-directions-v1 добавляет ровно одну меру каждой категории. Выбор версии
фиксируется до соревнования. В ней пары M1+M2 и M5+M6 недоступны.

## 3. Официальная формула

Обозначим x(m) ∈ {0,1}; a(m,d) = 1, если выбранная мера действует в районе d.
Для городской меры a = 1 во всех районах, для районной — только в выбранном.

```text
f(m) = (8 − L(m)) / 8
Δ(d,k) = Σ_m x(m) · a(m,d) · e(m,k) · f(m) + synergy(d,k)
I'(d,k) = min(100, max(0, I(d,k) + Δ(d,k)))
D(d) = Σ_k w(k) · I'(d,k)
D_avg = Σ_d p(d) · D(d)
D_min = min_d D(d)
N_crit = Σ_d Σ_k 1[I'(d,k) < 40]
Score = .7 · D_avg + .3 · D_min − N_crit
```

Сначала суммировать все эффекты и синергии, затем один раз clip. Иначе порядок мер
может изменить результат. Не округлять промежуточные значения; выводить два знака.
Для JS/Python double тестировать ожидаемые значения с допуском 1e-9. Для граничных
сравнений предпочтительны рациональные/десятичные величины; текущие эффекты кратны 1/8.

Синергии фиксированы и не масштабируются лагом:

| Пара | Прибавка | Территория |
|---|---|---|
| M1 + M2 | T1 +2 | Район M1 |
| M10 + M12 | B1 +2 | Район M10 |
| M5 + M6 | E2 +2 | Район M5 |

Пара включается один раз только при наличии обеих мер.

## 4. Разложение прироста

```text
ΔScore = .7 · (D_avg_after − D_avg_before)
       + .3 · (D_min_after − D_min_before)
       + (N_crit_before − N_crit_after)
```

Это точное аддитивное объяснение. Минимальный район может измениться — сравниваются
именно минимумы, а не всегда оценка Нуры. Диапазон Score снизу не ограничен нулём.

Не суммировать leave-one-out-вклады мер: синергии и штрафы могут учитываться дважды.
Если нужен аддитивный вклад каждой меры, опционально использовать Шепли:

```text
φ(m) = Σ_{S ⊆ N\{m}} |S|! (n−|S|−1)! / n! · [v(S∪{m}) − v(S)]
v(S) = raw_score(S) − raw_score(∅), n = 5
```

Требуется 32 поднабора. raw_score допускает неполные наборы только для внутренней
атрибуции; они не получают официальный статус допустимого игрового сценария.

## 6. Социальная модель — отдельный экспериментальный слой

Официальный Score не зависит от LLM, поддержки персонажей или этих коэффициентов.
Ниже проектная модель v1. Не выдавать её за измеренную удовлетворённость жителей.

Для жителя a района d и весов q из реестра:

```text
U_a(s) = Σ_k q(a,k) · I_s(d,k)            # 0..100, локальный индекс приоритетов
ΔU_a = U_a(after) − U_a(before)
c_a(s) = Σ_k q(a,k) · 1[I_s(d,k) < 40]  # 0..1, значимость критических провалов
b_a = clip(ΔU_a / 10, −1, 1)            # условная поддержка изменений
```

Позиция определяется двумя осями, чтобы положительный эффект не скрывал провалы:

- ΔU > 0 и c_after = 0: support;
- ΔU > 0 и c_after > 0: mixed;
- ΔU < 0 или (ΔU = 0 и c_after > 0): concern;
- иначе neutral.

Опциональное социальное распространение по нормированному входящему W:

```text
z_a(0) = b_a
z_a(r+1) = clip((1−λ) · b_a + λ · Σ_b W(a,b) · z_b(r), −1, 1)
λ = .2; максимум два синхронных раунда
```

Для экспертных узлов, если они входят в соседей жителя, z задаётся детерминированной
оценкой изменения соответствующих показателей, нормированной аналогично b; иначе
использовать социальные рёбра только между жителями и перенормировать W. Выбор
фиксируется в socialModelVersion. Для MVP предпочтителен второй вариант.
Узел без соседей сохраняет z = b. Реплики LLM не меняют z.

Это ограниченная модель влияния аргументов/контактов, не эпидемиологическая или
социологическая модель. λ = 0 отключает влияние. Сохранить локальный b отдельно,
чтобы UI показывал собственный интерес и социальный сигнал без смешения.

Если нужен общий индекс, только как «индекс синтетических персонажей»:

```text
U_synthetic = Σ_d p(d) · mean_{a in district d} U_a
```

Он не является новым официальным Score или процентом поддержки населения.
В первой версии достаточно индивидуальных U, ΔU и нерешённых проблем.

## 7. Поиск альтернатив

MVP: перечислить все замены одной выбранной меры на невыбранную и все переносы
районных мер, проверить ограничения, пересчитать. Применять hard constraints
пользователя до ранжирования. Фиксированная мера вместе с районом не изменяется.

Ранжирование по умолчанию: Score ↓, стоимость ↑, число изменений ↑, канонический ID.
Показывать до трёх различных наборов с точными дельтами и потерями.
При целевом показателе сначала применить согласованный минимум по нему, затем Score.

Локальный поиск не называть глобальным оптимумом. Для полного перебора:

1. Выбрать 5 различных ID из 14: C(14,5) = 2002 комбинации.
2. Отфильтровать бюджет, категории, глобальные конфликты.
3. Перебрать 5^r районных назначений для r районных мер.
4. Отфильтровать районные конфликты и пользовательские ограничения.
5. Рассчитать каждое назначение и сохранить лучший результат.

Можно кешировать результаты по каноническому набору + версиям данных/правил.
Утверждение «лучший» относится к заданной модели и ограничениям.

## 8. Время и ограничения причинности

Исходная формула задаёт только итоговый эффект с лагом. Она не определяет полноценную
квартальную траекторию. В MVP показывать фазы обсуждения и известные лаги, а не
выдуманные поквартальные показатели. Для реальной траектории нужна версия temporal-v2
с отдельным определением ввода в эксплуатацию, нарастания эффекта и синергий.

Датасет не моделирует число школьных мест, минуты поездки, реальные выбросы, расходы
на содержание или вероятность происшествий. Особенно явно отметить условную связь
M9 → S1: спорт-хабы повышают индекс по правилам, но не доказывают создание школьных мест.
Эти ограничения дают содержательные вопросы на общественных слушаниях.
